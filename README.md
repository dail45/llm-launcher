# Llama Launcher

Лаунчер для **llama.cpp** под Windows: пресеты запуска, калькулятор памяти (VRAM/RAM), несколько сборок и форков, единый OpenAI-совместимый роутер с автозагрузкой и выгрузкой моделей, доступ по локальной сети с паролем и API-ключами, загрузка моделей с Hugging Face и сборок с GitHub, бенчмарки, встроенный чат.

## Состав

| Часть | Путь | Что это |
|---|---|---|
| Ядро | `crates/core` (`lll-core`) | Вся логика: процессы llama-server, оценка памяти, роутер, REST API, SQLite, мониторинг GPU |
| Desktop | `app` | Приложение Tauri 2: окно + трей, ядро работает внутри процесса |
| Headless | `crates/launcherd` | То же ядро без окна — для службы / Task Scheduler / сервера |
| UI | `ui` | Svelte 5 + Vite; встраивается в бинарник и открывается в окне или браузере |
| Тесты | `tests` | e2e-тест с фейковым llama-server (`tests/e2e.sh`), демо-данные (`tests/ui_demo.sh`) |

Порты по умолчанию: **8090** — интерфейс и API управления, **8080** — роутер OpenAI API (`/v1/...`), **51000–51999** — внутренние порты llama-server.

## Сборка

### Через GitHub Actions (проще всего)
Workflow'ы запускаются **только вручную** — коммиты сборку не запускают.
**Actions → release → Run workflow**: укажите версию `X.Y.Z` (пусто — текущая из `Cargo.toml`) и отметьте, публиковать ли релиз. `.github/workflows/release.yml` соберёт на `windows-latest`:
- `Llama Launcher_*_x64-setup.exe` (NSIS) и `.msi` — установщики;
- `LlamaLauncher-portable.exe` — без установки (нужен WebView2, в Windows 10/11 он обычно есть);
- `launcherd.exe` — версия без окна.

- `SHA256SUMS.txt` — контрольные суммы.

При `publish` версия прописывается в `Cargo.toml`/`ui/package.json` (коммит «Release vX.Y.Z» в ветку), ставится тег `vX.Y.Z` и создаётся GitHub Release с файлами и автоматическими release notes. Без `publish` — только артефакты сборки (вкладка Summary запуска). Workflow `docker-build` (тоже вручную) проверяет кросс-сборку через Dockerfile.

### Версия
Единственный источник — `version` в `[workspace.package]` корневого `Cargo.toml` (Tauri и `launcherd` берут её оттуда). Версия видна в боковой панели и на экране входа, полная (с коммитом и датой сборки) — в «Настройки → О программе», в меню трея, в `launcherd --version` и в `GET /api/version`.

### В Docker (без Rust и Visual Studio на машине)
Нужен только Docker Desktop (WSL2). Кросс-сборка Linux → Windows (MSVC-таргет через `cargo-xwin`, установщик NSIS):
```powershell
.\build-windows.ps1
# или: docker build --target export --output dist .
```
В `dist\` появятся `launcherd.exe`, `LlamaLauncher-portable.exe` и `Llama Launcher_*_x64-setup.exe`. MSI в Docker не собирается (WiX работает только на Windows) — он есть в сборке GitHub Actions.
Первая сборка долгая (образ с тулчейном ~3–4 ГБ, скачивание Windows SDK), повторные — инкрементальные за счёт кэша BuildKit. Сборка подразумевает согласие с лицензией Microsoft на CRT/SDK, которые скачивает `xwin`.
Очистить всё: `docker builder prune` и `docker image prune`.

### Локально на Windows
Нужны: [Rust](https://rustup.rs) (MSVC), Node.js 20+, Visual Studio Build Tools (C++).
```powershell
cd ui;  npm ci;  npm run build;  cd ..
cargo install tauri-cli --version "^2" --locked
cd app; cargo tauri build          # установщики в target\release\bundle
cargo build --release -p launcherd # target\release\launcherd.exe
```
Разработка UI: `cd ui; npm run dev` (Vite на :5173 проксирует `/api` на запущенный лаунчер :8090).

## Первый запуск
1. **Сборки llama.cpp** → «Добавить папку» (каталог с `llama-server.exe`) или «Скачать с GitHub» (официальный llama.cpp и форки; для CUDA предлагается докачать cudart). Лаунчер читает `--version`, `--help` и `--list-devices`: форма параметров строится по реальному `--help` каждой сборки, поэтому флаги форков (например, `turbo3`) появляются сами.
2. **Модели** → добавьте папку с `.gguf` (split-файлы и mmproj распознаются автоматически) или скачайте с **Hugging Face** — там же видно, влезет ли квант в вашу VRAM.
3. **Пресеты** → «Новый пресет» или «Импорт команды» (вставьте существующую строку `llama-server ...`). Справа калькулятор памяти по каждому GPU и кнопки автоподбора `-ngl`, контекста, `--n-cpu-moe`, `--tensor-split`.
4. Укажите **алиас** — по нему клиенты обращаются к модели: `model: "coder"`.

## Роутер (OpenAI API)
`http://<host>:8080/v1` — `/v1/chat/completions`, `/v1/completions`, `/v1/embeddings`, `/v1/models` и т.д.
- Поле `model` = алиас пресета, имя пресета или алиас группы. Незапущенный пресет стартует автоматически; при нехватке памяти выгружаются давно неиспользуемые незакреплённые модели.
- **Стриминг** (`"stream": true`) передаётся без буферизации, включая `reasoning_content` — размышления модели видны в реальном времени (используйте `--reasoning-format deepseek` в пресете, либо модель отдаёт `<think>` в тексте — встроенный чат понимает оба варианта).
- Группа алиасов: один алиас → несколько пресетов по приоритету (например, «2×GPU → 1×GPU → CPU»).
- Нативный API инстанса: `http://<host>:8080/instance/<алиас>/...` (например, `/props`, `/slots`).
- Выгрузка по простою: TTL в настройках (по умолчанию 600 с) или в пресете; 📌 закреплённые не выгружаются.

## Аналитика токенов
Раздел **«Аналитика»**: каждый запрос через роутер (включая встроенный чат) записывается с числом **входящих**, **кэшированных** (взятых из KV-кэша llama-server, `cache_n` / `prompt_tokens_details.cached_tokens`) и **исходящих** токенов.
- Период: 24 ч / 7 / 30 / 90 дней / год; график по часам/дням — по типу токенов или по группам.
- Группировка: **модель**, **пресет**, **алиас**, **пользователь** (= API-ключ; запросы без ключа — отдельной строкой). Клик по строке фильтрует график.
- Экспорт в CSV, срок хранения настраивается (**Настройки → Память и запуск**, по умолчанию 365 дней).
- API: `GET /api/analytics?from=<unix>&to=<unix>&group=model|preset|alias|user&bucket=3600&tz=<сек>`, `GET /api/analytics/export`.

## Anthropic API (Claude Code и др.)
Роутер также отвечает в формате Anthropic Messages: `POST /v1/messages` (текст, картинки, tools/tool_use, thinking, стриминг SSE) и `POST /v1/messages/count_tokens`. Ключ — в `x-api-key` или `Authorization: Bearer`.
```powershell
$env:ANTHROPIC_BASE_URL = "http://127.0.0.1:8080"
$env:ANTHROPIC_AUTH_TOKEN = "lll_..."   # API-ключ лаунчера (если ключи созданы)
$env:ANTHROPIC_MODEL = "coder"          # алиас
claude
```
Запросы конвертируются в OpenAI-формат llama-server; токены попадают в аналитику как обычно. Для tool calling нужен пресет с `--jinja`.

## Игровой режим
Настройки → «Игровой режим» (тумблер, по умолчанию включён). Когда запущена игра из списка процессов **или** другая программа сильно грузит GPU (3D-движок ≥ 60 % или ≥ 3 ГиБ VRAM несколько секунд подряд; браузеры, Discord, OBS и системные процессы исключены), лаунчер выгружает модели и роутер не загружает их по запросам (503 с объяснением). Через N секунд после выхода из игры режим выключается; по желанию выгруженные модели запускаются снова. Можно включить/выключить вручную — в интерфейсе (плашка сверху) и в меню трея. Статистика GPU по процессам — через счётчики Windows (GPU Process Memory / GPU Engine).

## Качество квантов (perplexity / KLD)
Бенчмарки → «Качество квантов». Выберите кванты одной модели и (опционально) эталон — BF16 или Q8_0. Лаунчер прогоняет `llama-perplexity` из выбранной сборки по wikitext-2 (скачивается автоматически) или по вашему тексту и показывает PPL, ΔPPL, KL-divergence, 99-й перцентиль KLD и «Same top» с оценкой потерь. Файл вероятностей эталона временный (размер показан до запуска).

## MCP в чате
Настройки → MCP: подключение MCP-серверов (stdio-команда вроде `npx -y @modelcontextprotocol/server-filesystem C:\Users\me` или Streamable HTTP URL). В чате тумблер «🔧 Инструменты» передаёт их модели; каждый вызов показывается карточкой с аргументами и результатом и по умолчанию требует подтверждения (можно разрешить серверу выполнять без вопросов).

## Обновление лаунчера
**Настройки → ⬆ Обновление** (или пункт «⬆ Обновить до vX» в трее, значок в боковой панели). Лаунчер раз в 12 часов проверяет GitHub Releases (отключается там же; можно включить пре-релизы) и сам определяет тип установки:

| Тип | Как определяется | Что скачивается и как ставится |
|---|---|---|
| Установщик (setup.exe) | рядом с exe есть `uninstall.exe` | `*-setup.exe`, запускается тихо (`/S`) |
| MSI | exe в Program Files | `*.msi`, `msiexec /passive` (Windows спросит права администратора) |
| Портативная | всё остальное | `*-portable.exe`, заменяет текущий exe (старый остаётся как `.exe.old` и удаляется при следующем запуске) |
| launcherd | имя `launcherd*.exe` | `launcherd-*.exe`, замена exe |

Файл проверяется по `SHA256SUMS.txt` из релиза. Затем скрытый PowerShell-скрипт ждёт завершения лаунчера, ставит обновление и запускает его снова (с теми же аргументами, например `--data-dir`); запущенные модели останавливаются, открытая страница перезагружается сама. Данные (`%APPDATA%\LlamaLauncher` или `data\` рядом с портативным exe) не трогаются. Если репозиторий приватный, нужен GitHub-токен (Настройки → Загрузки). В Docker обновляйте образ: `docker compose pull && docker compose up -d`.

## Удалённый доступ по локальной сети
1. **Настройки → Безопасность**: задайте пароль (или `launcherd --set-password <пароль>`).
2. **Настройки → Сеть**: адрес интерфейса и/или роутера `0.0.0.0`. Можно ограничить подсети (CIDR).
3. Вход в интерфейс — по паролю (JWT, обновляемая сессия, защита от перебора). Клиентам роутера — **API-ключи** (`Authorization: Bearer lll_...`) с ограничением алиасов и права загрузки моделей.
4. **Пока нет ни одного API-ключа, роутер OpenAI открыт** — доступен без токена. Как только создан хотя бы один ключ, роутер требует ключ (кроме запросов с этого компьютера, если включено «Не спрашивать пароль на этом компьютере»).

Локальные запросы (127.0.0.1 без `X-Forwarded-For`) по умолчанию не требуют пароля — отключается в настройках.

### Телефон: мобильный режим и приложение (PWA)
На узком экране интерфейс переключается в мобильный режим: снизу вкладки «Дашборд / Пресеты / Инстансы / Чат / Ещё», в «Ещё» — остальные разделы, загрузка GPU/RAM, язык, тема, выход. Чат на телефоне: список чатов в выезжающей панели, Enter переносит строку, отправка — кнопкой.

1. **Настройки → Сеть и доступ**: адрес интерфейса `0.0.0.0`, пароль во вкладке «Безопасность», сохранить.
2. В блоке **«📱 Телефон»** отсканируйте QR-код камерой телефона (телефон в той же Wi-Fi сети).
3. Установка как приложения:
   - **iPhone / Safari**: «Поделиться» → «На экран „Домой“» — работает и по HTTP.
   - **Android / Chrome**: «Ещё» → «📲 Установить приложение» (или меню браузера). Chrome разрешает установку и офлайн-кэш только по **HTTPS с доверенным сертификатом**; по HTTP можно лишь добавить ярлык.

**Встроенный HTTPS** (Настройки → Сеть и доступ → 🔒 HTTPS): дополнительно к обычному HTTP-порту лаунчер слушает HTTPS (по умолчанию 8443) с вашим сертификатом и ключом в PEM. Где взять доверенный сертификат:
- **Tailscale** (проще всего, заодно доступ вне дома): включите HTTPS в админке Tailscale, выполните `tailscale cert имя-пк.хвост.ts.net` и укажите полученные `.crt`/`.key`; открывайте `https://имя-пк.хвост.ts.net:8443`.
- **mkcert**: `mkcert -install` и `mkcert 192.168.1.10` на ПК, затем установите корневой сертификат (`mkcert -CAROOT` → `rootCA.pem`) на телефон как доверенный.

Service worker кэширует только оболочку интерфейса (запросы к API и роутеру не кэшируются): приложение открывается мгновенно, а если ПК недоступен — показывает экран «Нет связи с лаунчером» с кнопкой «Повторить».

### HTTPS через обратный прокси
Вместо встроенного HTTPS можно оставить лаунчер на `127.0.0.1` и поставьте перед ним прокси; добавьте адрес прокси (`127.0.0.1`) в **«Доверенные прокси»**, чтобы лаунчер видел реальный IP клиента из `X-Forwarded-For` (для журнала, лимита попыток входа и фильтра подсетей). Прокси обязательно должен передавать `X-Forwarded-For` — запрос с loopback без этого заголовка считается локальным.

**Caddy** (`Caddyfile`):
```
llm.example.lan {
    tls internal
    reverse_proxy /v1/* 127.0.0.1:8080 { flush_interval -1 }
    reverse_proxy /instance/* 127.0.0.1:8080 { flush_interval -1 }
    reverse_proxy 127.0.0.1:8090 { flush_interval -1 }
}
```
**nginx**:
```nginx
server {
    listen 443 ssl;
    server_name llm.example.lan;
    # ssl_certificate ...; ssl_certificate_key ...;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_buffering off;            # стриминг токенов и SSE
    proxy_read_timeout 3600s;
    client_max_body_size 100m;
    location ~ ^/(v1|instance)/ { proxy_pass http://127.0.0.1:8080; }
    location / { proxy_pass http://127.0.0.1:8090; }
}
```

## Запуск как служба (без окна)
`launcherd.exe` — то же ядро без интерфейса окна (UI доступен в браузере).
- **Task Scheduler**: «Создать задачу» → триггер «При входе в систему» или «При запуске» → действие `C:\LlamaLauncher\launcherd.exe` → «Выполнять для всех пользователей» при необходимости. Для доступа к GPU лучше запускать от пользователя, а не SYSTEM.
- **nssm**: `nssm install LlamaLauncher C:\LlamaLauncher\launcherd.exe --data-dir C:\LlamaLauncher\data`.

Не запускайте одновременно desktop-приложение и launcherd с одним портом.

## Данные
`%APPDATA%\LlamaLauncher` (БД `launcher.db`, логи, скачанные модели и сборки). Портативный режим: положите рядом с exe файл `portable` (или `portable.txt`) — данные будут в `data\` рядом. Либо `--data-dir <путь>` / переменная `LLL_DATA_DIR`.
Бэкап/восстановление — **Настройки → Бэкап** (zip; файлы моделей не включаются).

## Тесты
```bash
cargo test -p lll-core
cargo build -p launcherd && bash tests/e2e.sh      # Linux/WSL, нужен python3
```
e2e проверяет: сканирование сборки и схемы, модели, пресеты, оценку памяти, роутер с автозапуском, стриминг и reasoning в реальном времени, логи, TTL-выгрузку, подсказку при OOM, группы алиасов, импорт команды, удалённый вход (JWT, ключи, права), экспорт, бэкап, отдачу UI.

## Что стоит проверить на реальном железе
- Мониторинг VRAM: NVIDIA — NVML; AMD/Intel — счётчики DXGI/PDH (системные). Калибровка пресета («Калибровать» при запущенной модели) уточняет оценку по факту.
- Установка сборок с GitHub (имена ассетов у форков бывают нестандартными — тогда добавьте сборку папкой).
- ROCm/Vulkan: выбор устройств идёт через `--device` по списку `--list-devices`.
